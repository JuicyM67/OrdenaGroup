# WP-00 · Projektgrund

Branch: `wp/WP-00-projektgrund` · Status: **godkänd 2026-09-26** · Beror på: – · Körs samtidigt som: WP-03 (copywriter, `src/i18n/`, `docs/content/`), utan överlappande filer.

---

## 1. Mål

Sätta upp en körbar och testad kodbas enligt D-003 (Next.js App Router i `src/`, TypeScript strict, Tailwind v4 som laddar `src/styles/tokens.css`, Bricolage Grotesque + Plus Jakarta Sans via `next/font`, ESLint/Prettier, Vitest, Playwright, Supabase CLI, `src/config/brand.ts` och CI). Paketet har inget F#. Det är förutsättningen för Våg A (WP-01, WP-02, WP-04) och är **klart när** en ren klon klarar `npm ci && npm run typecheck && npm run lint && npm run test` och startsidan visar tokens och typsnitt korrekt (se §7).

## 2. Utanför scope

- Skärmar, komponenter och design lab (`src/app/design-lab/`, `src/components/`). Det görs i WP-02.
- UI-texter och `src/i18n/es-CL.ts` (WP-03, copywriter). Startsidan visar bara `brand.name` och `brand.tagline`.
- Schema, migrationer, seed, pgTAP-tester, `src/types/database.ts` (WP-01). Varken `supabase start` eller Docker behövs.
- Format-lib, zod-scheman, `src/lib/`, `src/server/` (WP-04 och senare).
- Paketen för resten av stacken (`@supabase/ssr`, `zod`, `date-fns-tz`, Radix, `lucide-react` …). De installeras i det WP som använder dem, se FRÅGA 7.
- Vercel-projekt, deploy, `vercel.json`/region `gru1`, Sentry, PostHog, preview-miljöer (se FRÅGA 8).
- Env-validering med Zod (`src/config/env.ts`). Det görs i det första WP som läser hemligheter (WP-01/WP-16).
- Lint-regel mot hex-värden och godtyckliga Tailwind-värden. Den ligger i `IDEAS.md` och föreslås till WP-02.
- Att döpa om referensbilderna i `docs/design/screens/` (se FRÅGA 6).

## 4. Steg

**Scaffolding:** kör **inte** `create-next-app` i projektroten. Den vägrar eftersom katalogen inte är tom, och med tvång skulle den skriva över `.gitignore` och lägga till Geist-typsnitt och en egen `globals.css`. Beroendena installeras i stället med `npm install` och konfigurationsfilerna skrivs för hand. Behövs en referens går det att generera en mall i scratch-katalogen utanför repot och läsa den därifrån, men ingenting kopieras in utan granskning.

PR-förslag: **PR A** = steg 1–3, **PR B** = steg 4–6, **PR C** = steg 7–9. Det går också att göra en PR med en commit per steg om människan föredrar det.

## 6. Risker och öppna frågor

**Risker**
- **R1. `create-next-app` skriver över filer.** Undviks genom manuell scaffolding (se §4).
- **R2. Typsnittskrock.** Om `next/font` och `@theme` sätter samma variabel beror resultatet på CSS-ordningen. Löses genom steg 2 och fångas av e2e-testet. Klasserna måste sitta på `<html>` så att `var(--font-bricolage)` är definierad där `:root`-variabeln räknas ut.
- **R3. `next-env.d.ts` och ruttypning.** Nya Next-versioner genererar typer under `.next/types`. `typecheck` kör därför `next typegen` först, så att CI fungerar från en ren klon utan build. Om den installerade versionen saknar `typegen` checkas `next-env.d.ts` in och `tsc --noEmit` används direkt. Detta ska verifieras i steg 1.
- **R4. `next/font/google` hämtar typsnitt vid build.** Build utan nätverk misslyckas. Det är acceptabelt lokalt och i CI. Behövs offline-build senare går det att byta till `next/font/local` (kräver ett nytt beslut, eftersom DESIGN.md anger Google).
- **R5. Behörigheterna täcker inte `npx supabase`.** `.claude/settings.json` tillåter och nekar bara bara `supabase …`. Med CLI:t som dev-beroende finns det inte på PATH utanför npm-skript, och `npx supabase db push` / `npx supabase link` omfattas **inte** av deny-listan. Därför får planen inget generellt `supabase`-skript (`npm run *` är tillåtet och skulle kringgå deny-listan), bara namngivna och säkra `db:*`-skript. Se FRÅGA 4.
- **R6. `db:types` kan trunkera filen.** `>` tömmer `src/types/database.ts` om kommandot misslyckas. Ingen körning sker i WP-00. db-engineer gör skriptet säkert i WP-01 genom att skriva till en temporär fil och flytta den vid lyckat resultat.
- **R7. Tagline-ordet i copy.** "se llena"/"se llenó" är vanlig spanska och kan förekomma i `src/i18n/es-CL.ts` (WP-03). Namnisoleringstestet kommer då att slå till. Lösningen är att strängar som innehåller löftet använder `brand.tagline`, eller att i18n-filen får en explicit undantagslista i testet. Detta tas upp med copywriter.
- **R8. Konflikter i lockfilen i Våg A.** WP-01, WP-02 och WP-04 lägger alla till paket i `package.json` och `package-lock.json` parallellt. Vid merge-konflikt: ta `main`s version och kör `npm install` på nytt. Redigera aldrig lockfilen för hand.
- **R9. Parallella worktrees och lokal Supabase.** Alla worktrees delar `project_id` och portar, så bara en lokal stack kan köras åt gången. Det dokumenteras i README i WP-01.
- **R10. Referensbilderna har fel namn.** `docs/design/screens/` innehåller t.ex. `Panel del dueño · inicio@2x.png`, men `visual-diff.mjs` letar efter `Main.png`. `npm run visual` hoppar därför över allt, vilket inte stoppar WP-00 men stoppar WP-11–14. Se FRÅGA 6.
